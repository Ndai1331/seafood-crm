Quy trình đổi domain

1) Quy trình đổi domain brand S

Tool quản lý domain backup của Digital: https://domainpm.facilities.vip

Áp dụng khi có yêu cầu từ BOSS hoặc domain bị chặn.

  1. Dig làm request mở domain mới hoặc tắt redirect nếu domain cũ đang redirect, sau đó đem đi check chặn (QC thực hiện).
  2. Sau khi có kết quả check chặn, process request tới SA để đổi domain và ghi rõ lý do đổi (Dig thực hiện).
    Thông tin cần có trong request gửi SA:
    • Brand, domain cũ, domain mới, trạng thái redirect hiện tại và ngày bắt đầu request.
    • Lý do đổi domain rõ ràng (bị chặn, chiến dịch mới, bảo trì).
    • Link kết quả check chặn do QC thực hiện kèm người kiểm tra.
    • Bảng phân công QC nhánh để SA biết người nhận kiểm tra lại.
    • Thời gian mong muốn hoàn tất, người chịu trách nhiệm follow.
    Mẫu nội dung:
    Brand: S
Domain cũ: domaincu.com (đang redirect sang domainbackup.com)
Domain mới đề xuất: domainmoi.com
Lý do: Domain cũ bị chặn ISP, cần đổi gấp trong ngày.
Check chặn: https://task9.pro/report/12345 (QC Anh.AnhQC)
QC follow: QC S nhánh 1 - Anh B
Thời gian mong muốn: trước 17h hôm nay.

  3. Khi SA thông báo domain đã done → tag QC nhánh (Dig hoặc QC thực hiện đều được) tương ứng để họ check nhanh (file có note QC nhánh nào cho brand nào).
    Nội dung cần gửi khi SA báo hoàn tất:
    • Xác nhận SA đã đổi và cung cấp bằng chứng (ticket ID, timestamp).
    • Tag đúng QC nhánh phụ trách brand (dựa bảng phân công trong sheet).
    • Đính kèm checklist test nhanh: truy cập domain, test login, kiểm tra redirect.
    • Nhắc QC update trạng thái ngay khi kiểm tra xong.
    Mẫu tin nhắn tới QC:
    SA báo domainmoi.com đã active lúc 15:42 (ticket #SA-4582).
@@QC_S1 kiểm tra:
- Truy cập domain mới trên PC/Mobile.
- Test flow đăng ký/đăng nhập.
- Test redirect từ domaincux.com.
Báo lại trạng thái trước 16:00 nhé.

  4. Sau khi QC nhánh Report check xong và báo OK / Done.
  5. Dig process redirect các domain cũ về domain mới. (QC có sẵn list redirect nên có thể tự request nếu không thấy Dig)
    Danh sách redirect cần chuẩn bị:
    • Liệt kê domain cũ, www-domain, subdomain liên quan, kênh traffic.
    • Ghi chú trạng thái hiện tại (redirect tới đâu, off/on, cần off tạm).
    • Chỉ định thứ tự ưu tiên nếu có nhiều domain.
    • Đính kèm file excel hoặc bảng để Dig/SA thao tác hàng loạt.
    Ví dụ bảng redirect:
    | Domain               | Trạng thái | Redirect tới           | Ghi chú        |
|----------------------|------------|------------------------|----------------|
| domaincu1.com        | ON         | domainmoi.com          | Đã off ads     |
| www.domaincu1.com    | ON         | domainmoi.com          |                |
| landing.domaincu1.cc | Đang OFF   | domainmoi.com/register | Bật sau khi QC |

  6. Khi SA báo DONE redirect → QC check lại redirect tại link (https://task9.pro/check-redirect) toàn bộ domain cũ + www. xem đã đúng chưa sau đó (QC hoặc DIG) báo lên nhóm DOMAIN NOTI_ALL về domain mới đã đổi.
    Mẫu thông báo sau khi redirect hoàn tất:
    [Brand S] đã đổi domain thành domainmoi.com (done lúc 18:05 12/10).
Redirect:
- domaincu1.com → domainmoi.com (QC @@NamQC kiểm tra OK)
- www.domaincu1.com → domainmoi.com (QC @@NamQC kiểm tra OK)
- landing.domaincu1.cc → domainmoi.com/register (QC @@TrangQC kiểm tra OK)
QC đã test trên PC/Mobile, login/đăng ký hoạt động ổn.
Đã cập nhật sheet Redirect Tracking tab Brand S.
    Nhắn trong nhóm DOMAIN NOTI_ALL và pin lại trong 24h.

2) Quy trình đổi domain brand G

Tương tự brand S ở khâu mở/tắt redirect và process request, nhưng lưu ý bộ 3 domain.

Lưu ý: Con G có 1 bộ 3 domain, khi request phải ghi đủ cả 3.
Ví dụ bộ 3 domain:
iwin.net
play.iwin.net
dangky.iwin.net
  1. Thao tác request tương tự brand S:DIG yêu cầu tắt redirect hoặc mở domain backup OFF để check chặn. QC Follow kỹ để tránh thiếu 1 trong 3 domain.
  2. Webgame (play.iwin.net) khi QC bên G test xong sẽ báo done. (Follow group QC & GB để nắm thông báo)
  3. QC Test các LDP đã dựng cho iwin.net và dangky.iwin.net theo checklist bên dưới:
    • Test content đã đổi đúng chưa (text phù hợp site mới).
    • Test link social (Facebook / Telegram / Live Chat) mở được không.
    • Test nút CNBW trên PC / Mobile trỏ đúng link chưa.
    • Test Tải app / Link tải app / APK trên Android, iOS: tải đúng app, mở và load ổn.
  4. QC Process request Dev.MarT để trỏ login vào webgame mới.
  1. Sau khi trỏ xong và báo done → QC báo cho Dig process redirect cả cụm domain cũ (các domain cũ đang trỏ redirect tới).
  2. Khi SA báo DONE redirect → QC check lại redirect đã đúng chưa và báo nhóm DOMAIN NOTI_ALL về domain mới.
    Checklist redirect cụm domain brand G:
    • 3 domain bắt buộc: domain chính, webgame (play), đăng ký/landing.
    • Sau khi trỏ, test login webgame, vòng đời user (nạp, rút nếu cần).
    • Kiểm tra link tải app từ các LDP có đổi sang domain mới.
    • Cập nhật sheet `Brand G - Redirect` cột `Ngày hoàn tất`, `Người test`.

    Thông báo mẫu tới các nhóm liên quan:
    Brand G: Domain mới domainmoi.net đã live lúc 20:15.
Login webgame (play.domainmoi.net) hoạt động, QC @@LongQC test và xác nhận.
Các LDP (dangky.domainmoi.net, landing) đã cập nhật link app, CNBW chuẩn.
Redirect toàn bộ iwin.net bộ 3 sang domain mới -> QC @@AnQC kiểm tra OK.
Đã cập nhật sheet Dev.MarT + Redirect tracker.
    Gửi đồng thời cho nhóm Dig, QC G, Dev.MarT và DOMAIN NOTI_ALL.
